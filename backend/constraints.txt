# Pinned dependency set for CI. The backend's equivalent of frontend/package-lock.json.
#
# Why this file exists
# --------------------
# pyproject.toml declares version *ranges*, so `pip install -e ".[dev]"` resolves whatever is
# newest at install time. That made CI unreproducible: dev went red between two pull requests
# that changed no backend file, because alembic 1.19.0 was released in between (issue #47).
# A green run has to stay green until someone deliberately changes something.
#
# This is a constraints file, not a requirements file. It pins the version pip may choose for
# a package without asserting that the package is installed at all, so it stays correct across
# platforms: the entries below that are Windows-only (colorama, tzdata) are simply unused on
# the Linux runner. pyproject.toml remains the single source of truth for what the package
# *requires*; this file only decides what CI *installs*.
#
# How to regenerate
# -----------------
# Deliberately, in its own pull request, so a dependency bump is reviewed like any other change:
#
#     cd backend
#     python -m venv .venv-lock && .venv-lock/Scripts/activate   # Linux: .venv-lock/bin/activate
#     pip install -e ".[dev]"                                    # no -c: resolve freely
#     pip freeze --exclude-editable | sort -f > constraints.txt   # then restore this header
#
# Run the full suite against the result before committing it.
#
# Resolved 2026-08-04 on Python 3.11, the version CI runs.
